# GTM agent recipe

- **Recipe:** One agent for the gtm function, with the sales and marketing cards, run against two measured goals. A recipe shows the shape; every value in angle brackets or quotes is a placeholder to replace from the company's own records.
1. Roster first. Read list_company_agents. If an agent already owns demand, outreach or posting for this company, update it (manage_company_agent mode='update') and stop. Create only when none does. One agent serves the parent function; sales and marketing are its child cards, not separate agents, unless a different risk class, grant or cadence justifies a split (`cady-company-manage-agents` step 1).
2. Two goals, each a work item with workKind 'goal' (submit_company_work_checkpoint) and a measured target in brief.target {count, unit, by, definition}:
- Pipeline to qualified calls: count qualified calls booked by a date. 'Qualified' is defined once in the goal's definition (who, what they confirmed), not per message. Agent stages: contacted, replied, call booked, call held.
- Posting cadence: count posts published per week. The definition says what counts as published and where.
Read the company's direction first (read_cady company:direction); a goal that contradicts it is raised as an ask, not filed.
3. Create the agent: manage_company_agent mode='create', expectedRevision null, with name '<Growth (Company)>', function 'gtm', pack 'gtm', goalId (the pipeline goal; the posting goal is cited from its work items), goalText (one sentence of the continuing responsibility), approvalLimits (prepare only until a grant is active; never send, post or book without the review or grant that covers it), riskClass 'critical' (it can reach people outside the company), cadence (for example {kind:'daily', every_n:1, at:'09:00', tz:'<IANA zone>'}; one cadence per agent, so replies are seen no faster than the next run), dutyOrder (one duty per line: replies first, then due follow-ups, then the day's first touches, then the day's post, then the weekly funnel review), and skills ['`cady-gtm-tam-map`','`cady-gtm-cold-email-cycle`','`cady-gtm-warm-email`','`cady-gtm-linkedin-message`','`cady-gtm-reply`','`cady-gtm-pipeline-pass`','`cady-gtm-calls`'] plus the content skills the company uses for posts. Bind with installedSkills {id: version@tag} from the SKILL.md headers, read back the binding, and stop at go_live until the owner approves (step 7 of the manage-agents skill).
4. Outreach path. Each batch is prepared with crm.prepare_outreach_review for the exact recipients and text, read back with crm.get_outreach_review, then released under the company's mode for the external category (the permission_modes line in get_cady_context companyValues) or an active grant (crm.list_outreach_grants reads them). Each recipient's permission to contact and fit note is read first (crm.get_party, readiness.nextAction). Follow-ups are their own reviews under the grant's follow-up delay. Replies follow `cady-gtm-reply`.
5. Posting path. A post is an effect in the external category: prepare the text as a Files document cited from the work item, judge it with the taste check (post part), and publish only under that category's mode or a grant. Where no publish review is available to the host, the post waits as a BLOCKED ask with the exact text, and the agent says so in its report instead of posting.
6. Taste check. Before a message or post is prepared for review, judge it with the taste check, using its message part for outreach and its post part for posts. The check is a set of compact questions answered from evidence or by a fresh reader; the person's edits to the review are the feedback that counts.
7. First task. One cycle at the finish line, prepare-only: build or confirm the list, prepare one small batch and one post, and report. Its brief.doneWhen holds 2-5 reader-test lines tagged (check), (fresh) or (person), for example '(check) every recipient in the batch has a readable permission and fit note', '(fresh) a reader who sees only the draft and the profile can say why it was sent to this person', '(person) the owner approved or edited the batch before anything was sent'. brief.stopIf names the limit that ends the cycle early.
8. Tell the person plainly what the mode means. If the external mode is notify, sends and posts approved by the agent do not wait for them; say so before go_live and offer the Settings change to approval if they want to see each one first.
9. Review. After the first released cycle read the effects (replies, bounces, opt-outs, posts live), then review on a signal. Improve one thing per repeated failure through the Change agent behaviour card.

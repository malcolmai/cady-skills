# Product system map template and drafting

**Point:** Give agents one versioned map of how a product works, written once and found by signpost.

- **Template:** System map template. Fill it for the product, keep what helps and drop what does not; it is a start, not a form. Each page opens with its point and a bet on how best to do it (`## <page>`, `Point: ...`, `Bet: ...`), then its content. One home per fact: decisions stay decisions, and the map cites them by subject. 1. Point and bets: why the product exists, for whom, and the bets it stands on. 2. Journeys: user outcomes in lifecycle order, each with its acceptance. 3. Architecture: one simple diagram and the owner of each part. 4. Dimensions: each with id, one owner, one question, label (differentiating or not, with reason), the quality classes it crosses when built in code, and the active set. 5. Loops: the recurring loops that keep the product working, each with its trigger and owner. 6. Roadmap: ordered next slices, each citing the journey or dimension it serves. Leave off scope, pricing and ICP (direction), rules (decisions), findings and status (work).
- **Drafting:** Drafting a system map. First read records_read decision:product:system-map-<product>; if it exists, read its File and update the map at its writer instead of starting another. Otherwise find the single writer from the host: the repo for software, else a Notion page or an HTML template you edit. Draft from the template. Publish one Cady File, Markdown or PDF (export a Notion or HTML writer to one of them; Files takes no HTML): `cady files upload <path>` once, then `cady files upload <path> --file <id>` for each new version. Signpost it once with decisions_write: subject product:system-map-<product>, layer L2, appliesTo the product's classes (context.read, engineering.architecture, product.scope), chosen naming file:<id> and the writer's URL; L2 makes it a signpost that product-area context serves. The decision holds the pointer, the File holds the map. A new map or a larger change gets a review per cady-engineering-independent-review.

# Release plan

- **Plan:** Size each release as a usable customer tool: a narrow MVP on cheap infrastructure, with the research and architecture to reach best in class. When the open question is whether an idea is worth building, propose a small concept demo instead and label it a demo. Do not release intermediate steps nobody can use. Match planning effort to uncertainty and consequence. Reuse sufficient current research; a clear correction can proceed directly. Resolve material scope ambiguity against the applicable domain outcome and approved direction with bounded stronger-model advice or the reserved owner decision before dependent work. Plan the lowest catching checks with the work, consolidate acceptance fixes, and stop once acceptance is proved; broaden or repeat only for changed behavior, new failures or unresolved concerns. Preserve applicable acceptance and quality thresholds. For Product work where quality levers could change the build decision, reuse or prepare only the relevant profile levers with source, bar, current state (or unknown) and feasibility; a narrow correction or non-Product task need not create a profile. Release thresholds go in the release work item's brief.doneWhen (up to 5 lines) and cite applicable levers alongside correctness, authority and safety, user journey and design, and cost where relevant. Where build shape is open, run the cheap experiments that decide it first. Don't build a lever that cannot reach its bar; adopt, or label the release a demo. Estimate build, QA and review separately from observed agent latency and cost where available; do not infer an AI time quota from human effort. A release is a Projects work item, not a Product bet. On the company work checkpoint use productId when binding the work to a customer product, and include typed release {name, stage: planned|build|qa|released, buildBy, qaDays (0-60), stories (up to 12 story ids this release changes; once accepted as shipped each reads re-walk due)}; thresholds are brief.acceptance, not a release field; dueDate is the release date. Read back the checkpoint.

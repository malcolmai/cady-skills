# Agent setup

Create: agents_set with the responsibility in duties, the installed skills, limits, and triggers: [] for on-demand or one schedule object or {kind:'event', on:'<description>'} in an array. A schedule is the cadence object itself; the returned event state is configured_unconfirmed until a matching host subscription is read back. Pass goalId separately when the agent serves a linked goal. In the same run, file the first task with its agentId, goalId and brief (run sequence step 5).
Bind: agents_change mode bind_host, targetAgentId and installedSkills listing every installed library skill as {id: version} or {id: version@tag}, copied from its SKILL.md header, including its role card and the run sequence (any spelling of a skill resolves to one; an unknown one is refused with the nearest valid id). Schedule install, only on request (reference scheduling): install the recurring host task, read it back and add hostTaskRef and readBackAt to the binding.
Run and go live: run the first task as the agent; report with work_write and evidenceRefs, and the report counts as the first result. agents_change mode go_live once the binding still matches; read back the receipt. Use agents_set with propose true only when the design needs effects outside your limits or this host may only propose.
Privacy: change visibility or sharing only on request, with their exact words. An agent's privacy (private, shared or public; default private) covers its runs, run results, evaluations, cost, refusal log, prompt, design and trigger; admins see it only when they turn on See everything; its work, results, decisions and notes are company record every member reads unless marked sensitive.
The owner's own decision covers a grant (send, spend, publish, sign, file), an invite, a share, outreach in approval mode, new access, widening permissions, a design change to a grant-holding agent and higher cadence or cost; per grant when critical.
Create with expectedRevision null; the first task is filed in the same run. Show the first task's decision map for approval before go-live.
When none of step 7's owner decisions applies, Cady records a policy approval at go-live. With the owner absent, record agent.approve:<agentId> as a BLOCKED decision item (decidedBy: the member who will approve), delivered as asksForYou, and complete that same workId only with their quote; reuse a current one for unchanged terms. A task handoff grants no rebind or agent migration. A grant activates only through reviews_confirm under its owner's matching COMPLETE decision; only its owner resumes an anomaly-paused grant (crm_outreach_grants_update mode request_resume).

# Agent design

Design inputs: agent name and function; one goal; risk class; measure and its data (the target and readings live on the goal it serves); cadence or trigger, with why; approval limits; tool pack; owner member; first task, its checks and evaluation criteria; end or escalation condition.
Authority inputs: a verified member credential; host identity from the current Cady connection; expectedRevision null for a new agent or run, or the current revision for a change; current targetAgentId for changes. Omit decisionId and nonce (the server fills them) unless retrying an exact call.
Scope: one recurring agent per goal or sub-goal (decision product:company-model), normally one per function in use, with the role cards and skills it needs installed. Parallel sessions are runs of that agent, not new agents, and so are subagents doing its tasks. Split a child agent out only for a different risk class or grant, or a different cadence or host (the safety-isolation exceptions); parallel work alone is not a reason to split. A channel execution agent with its own sending account or grant may be split under this rule.
Responsibility: a cadence is set by duty, deadline and evidence freshness; a research agent's responsibility is named key questions (`cady-company-decision-questions`); the function head keeps the decisions. Critical covers sending or publishing to non-members, spending or committing money, signing, filing, inviting or sharing data externally, changing external accounts or access, deleting owner records, or drafts released automatically by a grant, scheduled task or other agent.
First task and evaluation: one cycle of the real deliverable at its finish line; a standard agent's first task touches each tool the duty needs. Each brief.doneWhen line is a reader test (a yes/no question a reader without context can answer), tagged (check), (fresh) or (person) by who can verify it; brief.stopIf holds the limit that ends the run early (staying within limits is always one). Agent-level limits and assignment stay in limits and duties. Ask once for missing inputs, accounts, grants or scheduler; no secrets in chat.
Re-class and prepare-only test a new path on any grant, tool, access or trigger change. goalPriorityRef is priority evidence, not permission. For substantive drafting or adaptation, follow `cady-company-taste-review` step 3 and its conditional drafting reference; skip it for obvious corrections. A fork of the library is optional and only for a deliberate company edit, with its baseline tag; record why in the commit.

# Scheduling

Wake for a useful action or signal, not to keep an agent busy. The host schedules and executes; Cady runs no scheduler and holds the work, checkpoints and results. Only host readback establishes a configured recurrence, and only a reported result proves a run.
Every run of every agent follows the run sequence (skill cady-core-run-sequence). Waiting work records nextAction and a dueDate and relies on the host's next wake; there is no separate wake mechanism. Dated reminders (renewals, notice deadlines, filings) are due items in company work, read by the bound agent through get_company_work, never a separate reminder, calendar file or schedule.
Cadence: Reuse the authorized cadence and actual host or spend limits; otherwise fit cadence to evidence freshness and deadlines without inventing a time quota. Actionable work continues until done or an actual limit; waiting work checks near the expected reply or deadline and backs off empty checks; with no ready work, stop the run and keep the next useful trigger. Coalesce or skip missed runs; never replay a backlog of external effects. Distinguish a finite task from a continuing responsibility; justify recurrence by duty, deadline and evidence freshness under the actual host scheduler, not a fixed role-to-daily rule. The Orchestrator retains its current daily contract.
Since your last pass: read list_recent_changes from the time saved on your work item, paging back with its cursor; after a complete pass save this pass's start time, overlapping the boundary and deduplicating change ids. A change pointer is a reason to re-check, never a completion verdict.
Runtime: Choose the lightest capable runtime: a script for deterministic work, a supported native host schedule for periodic work, an always-on external agent only when response time justifies its cost and security burden. Verify the actual host's scheduler, persistence and tools before promising unattended work; local execution cannot run while the machine is off.
Host scheduler: the create result's install block names this host's scheduler and how to read it back. In Claude Code that is /schedule (a cloud routine, scheduleKind cloud_routine), a Claude Desktop scheduled task (desktop_task, the computer must be awake) or /loop in an open session (loop, ends with the session); Codex uses an automation or cron (cron). A host with no scheduler (Gemini CLI, Grok) cannot run the agent unattended: say so plainly, and use an OS cron only if the owner asks. Pass scheduleKind, hostTaskRef and readBackAt at bind.
Models: The host owns model and effort selection. Preserve explicit user settings and use supported host controls; when selection is unavailable, use the configured executor.

# Outreach release

**Point:** Release only reviewed, authorized exact copy and check the outcome, so no message leaves without permission or a receipt.

- **Permission:** Read the party with records_read party:<partyId> before drafting, including its fit, engagement and destination. Follow readiness.nextAction and act on each hold or refusal’s next call; never guess around it or clear an opt-out or suppression. An active deferral or an invalid verification blocks approval and release. Unknown verification can be approved but is held at release. For unverified destinations, use the verifier the owner names, or ask the owner which provider to use. Record a contact basis only when a governing decision states it; otherwise report the hold. The holds no_basis, sender_missing and destination_unverified block release, not preparation: prepare the review anyway.

## Preparation

Call find_cady_tools with {"detail": "schema", "tool": "crm_interactions_write do message"}: When exact recipients and copy are ready, claim the matching skill’s work item, then prepare the native held review. Read it with records_read review:outreach/<approvalId>. Follow current preparation readiness, even when an older next action names a different order.

## Release

- Read and fix: every outreach review carries its relationship type (customer, investor, partner or supplier), and release puts each recipient on that board only. Read the review with records_read review:outreach/<approvalId>, fix refusals and prepare again. Say a message "can go out" only when no review is held; otherwise name each hold, and follow readiness.nextAction (owner_review: present the review; wait: leave release pending). Approval: follow the one approval rule under execution authority in cady-core-execution. Checkpoint: Until approved, checkpoint OPEN with nextAction 'awaiting approval of review <approvalId>', the review ref and release: true (gives up your claim). Work report: Then close the run with work_write: the run's outcome and the held review ref; the work's result waits for release.
- Follow the one sending rule under execution authority in cady-core-execution.
- Server email or a device route: when approved (72 hour window), claim again, confirm crm.get_outreach_review mode 'approved' (workId; reach it with find_cady_tools, then call_cady_tool) matches your inputs, then call crm_interactions_write do send with workId and expectedGeneration. Pass the returned ticket ids to the named executor (Cady's server, or the user's cady CLI with executor=device). On RELEASE_PAUSED: keep preparing, leave release open, ask the owner to resume, and do not retry. Under an agent stop, prepare nothing more on that account and do not ask. Never send yourself on this route; a message crm_interactions_write do send returns to you follows the own-tool rule. Keep receipts and reconcile any uncertain send before retrying. Report once with work_write; without release authority, say so and leave the item open.
- Own-connector or agent sending tool, one rule on any channel (the local LinkedIn MCP server, or your own mail tool when no Cady mailbox is connected or by choice): get approval as above, then use that tool; when readiness.nextAction is crm_interactions_write do send, send exactly each message it returns. An email with a tracked link uses the review's minted link with descriptive anchor text. Record each explicit outreachOutcome with crm_interactions_write, including readiness.nextAction's exact approved channel, destination and copyHash; a general note never counts as sent. Schedule the follow-up with crm_entities_write mode update_track (nextAction, nextActionDueAt = send time plus the grant followUps.delayDays, or the delayDays you prepared), which the due follow-ups view reads. Hold while readiness.nextAction says paused or cap reached, and hold the channel's pacing yourself.
- External CRM (company.modules crm source external): prepare with recipients (addresses) instead of partyIds, get approval as above, then check opt-outs, send and record the outcome in that CRM. Cady records nothing on this route.

## Outcome check

- Before any follow-up preparation or grant-covered run, detect replies with one rule per channel. Email Cady sent from a connected mailbox: first call crm_interactions_write do capture. Cady reads that mailbox for replies, opt-outs and bounces to mail it sent and records them, and returns the new replies by party; read only those threads for reply work. Capture files each under the provider message id (Graph: the immutable id), so recording the same message again returns already_recorded. If capture is incomplete or names a gap, triage that window with your connector before any follow-up. Record what capture cannot see (an opt-out in prose, own-connector email, LinkedIn) with crm_interactions_write do record, sourceRef = the provider message id.
- LinkedIn: on the account's executor (the signed-in device or browser), read each released recipient's thread and note any new inbound message and latest_outbound_at, the newest outbound message in that view; omitted means not reported, never none. Match each message to its party and approval with records_read review:outreach/<approvalId>; file it with crm_interactions_write, sourceRef = provider message id (LinkedIn: thread id plus message time); never paste a message body or quote into note.
- Kinds: reply or inbound; bounce with bounceType hard or soft and destination; opt_out with channel all, email, linkedin or marketing (destination optional: record a LinkedIn or call stop by partyId) and optOutReason complaint if so. A hard bounce suppresses its address; opt_out blocks the party on that channel scope in the same receipt; a soft bounce only records. Send one hard bounce or opt_out per call; batch replies and soft bounces up to 25. A reply or inbound message after the last release blocks follow-ups.
- Check grantsPaused for grants paused by the result; grantPausesPending pause at their next release, or pause them now with crm_interactions_write do grant_pause.
- 'Stop', 'unsubscribe' or 'remove me' is opt_out on the channel they named, else all.
- A 'not now' is a reply: record it and set re-contact with crm_entities_write mode update_track recontact {policy: '1m'|'2m'|'3m'|'6m'|'date'}. File it; the reply is a separate work item.
- An ambiguous or positive reply is a reply, not an opt-out, and an interested lead is never dropped.
- If the mailbox or thread cannot be read, stop follow-ups on that channel and say so.

## Follow up

- Every follow-up is its own review: crm_interactions_write do message with followUp {delayDays, nonRepliersOnly: true}, never inside a cold cycle. Prepare it only after the outcome check finds no reply since the last release; hand a recorded replier to `cady-gtm-reply`. Under a grant, its followUps {max, delayDays} also bound count and spacing. Email follow-ups use `cady-gtm-warm-email`; LinkedIn allows one, in `cady-gtm-linkedin-message`. A follow-up to someone with no engagement on record who has not replied: at most 2 after a first touch, at least 3 days apart, each counted toward the company cold email quota. Stop on a reply, no, opt-out or suppression. A follow-up to an engaged recipient (a customer or partner, a recorded human interaction, an inbound message): paced, not counted toward the cold quota and with no count limit. For engaged recipients: follow the thread's tempo: wait about as long as they took to answer last, or 2 to 3 business days when unknown; never more than one unanswered note in 2 business days; lengthen the gap after each unanswered note. Each note adds something new or closes an open item.
- One count: Cady decides per recipient at release whether a send counts toward the cold email quota (unengaged counts, engaged does not); never pick the lane or the followUp flag to change it. Only human clicks count as engagement: attribution links record human and non-human clicks separately.

# Goals, asks and work

Choosing work (agents): resumeWorkIds first, then openWorkIds whose dueDate has passed or is empty, in the order served. Founder outcome: Surface any open founder outcome no live acceptance covers before routine work. Acceptance: the function owner reconciles stale or missing acceptance and next action with a founder outcome before assignment or continuation: retain the existing item where it fits, claim it before editing its brief, and record the reason and governing outcome ref. If it no longer fits, cancel it with work_write {id, status: cancelled, note, evidenceRefs}, note saying why and evidenceRefs naming the replacement work; a note alone leaves it live. Someone else's live claim waits for its executor to acknowledge. Route a change outside your authority to its owner; a different outcome grants no effect permission. Scope: use the reconciled task headline, brief.doneWhen and current outcome as the working scope; add goal or constraints only when they change the action or acceptance. Creating work: work_write {kind: task or goal, headline, next, path (its node) or goal (one, not both), brief} makes it; {id, ...} changes it, status (open, working, blocked, done, cancelled) moves it and note adds a fact. Read for an item already covering this unit (same skill, segment or persona key and cycle) and reuse it; cancel a duplicate you opened with the reason in the same run. Create owner work only when needed. An ongoing responsibility stays open between runs. Asks you filed (asksFiled in your context): for each in waiting, do one quick check if one exists: access, call the tool once; a decision with decides, read that decision; send or sign, read the receipt or interaction. If it is resolved, close it (work_write {id, status: done, result: "Resolved: <what you checked>"}) and continue; otherwise keep it and work on the rest. Never assume either way. Act on the answers in answered; "Handled elsewhere" means a person marked it handled, so verify it the same way and, if the check fails, raise the ask again. Goal calls: when a goal's callReasons or measureDue name a call, record a reading first (work_write {id: the goal's id, measure}), then the goal call (`../../../references/company-goals.md`). No work: if neither work nor a standing duty is due, a goal owner reviews its open goal against the goal's doneWhen and dimensions first (its role method says how); go to step 6 with outcome no_work only when that finds nothing material.

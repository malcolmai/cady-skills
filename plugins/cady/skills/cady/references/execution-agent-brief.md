# Execution agent brief

## Record

- Agent record: agents_create, expectedRevision null. Name '<Channel> (<Company>)'; function 'gtm'; riskClass 'critical'; effects ['send'] (['publish'] for a posting agent); goalId and parentAgentId (the GTM strategy agent). State the split reason in each record: this channel has its own sending account and grant, so an account stop is isolated.
- Duties: one sentence of responsibility, then replies first, due follow-ups, today's first touches, report. Limits: day and week caps; 'prepare only until grant <grantRef> is active'; 'stop under `agent-stop.md`'; never research or rewrite the persona, segment or offer: a missing brief ref is a stop and a report to channel strategy.
- Skills: that channel's execution skill only, plus `cady-gtm-reply` when it owns the thread and `cady-gtm-warm-email` for email follow-ups. Pin installedSkills {id: version@tag} from the SKILL.md headers for binding. Set triggers: []; recommend a cadence with why in the report, including how soon replies are seen.
- **First task:** one prepare-only cycle that releases nothing; say so in its brief. Use work_create with methodId = the channel execution skill's id (for example `cady-gtm-cold-email-cycle`) and current methodVersion, agentId, goalId, and evidenceRefs for the List or partyIds. The brief carries refs, never copies: no quotes, disqualifiers or offer text from the persona File or decisions; the channel execution skill reads them through profileRef. Include profileRef (persona File id), offerRef (accepted offer File or decision), listId or partyIds, segmentKey, cycleKey; angle and variant names and the hypothesis subject they test, not copy; senderLabel, grantRef (or grant terms to propose), voice and brand pack subjects; governing decision refs for strategy, targets and the pre-registered keep/scale/kill rule. Set brief.doneWhen to 2-5 reader tests tagged (check), (fresh) or (person), and brief.stopIf to the limit that ends the run early.

# Agent setup

Create: agents_set or agents_update or agents_change mode='create' with the responsibility in duties, the installed skills, limits, and triggers: [] for on-demand or one schedule object or {kind:'event', on:'<description>'} in an array. A schedule is the cadence object itself; the returned event state is configured_unconfirmed until a matching host subscription is read back. Pass goalId separately when the agent serves a linked goal. In the same run, file the first task with its agentId, goalId and brief (run sequence step 5).
Bind: mode='bind', targetAgentId and installedSkills listing every installed library skill as {id: version} or {id: version@tag}, copied from its SKILL.md header, including its role card and the run sequence (any spelling of a skill resolves to one; an unknown one is refused with the nearest valid id). Schedule install, only on request (reference scheduling): install the recurring host task, read it back and add hostTaskRef and readBackAt to the binding.
Run and go live: run the first task as the agent; report with work_write and evidenceRefs, and the report counts as the first result. mode='go_live' once the binding still matches; read back the receipt. Use mode='propose' only when the design needs effects outside your limits or this host may only propose.
Privacy: change visibility or sharing only on request, with their exact words. An agent's privacy (private, shared or public; default private) covers its runs, run results, evaluations, cost, refusal log, prompt, design and trigger; admins see it only when they turn on See everything; its work, results, decisions and notes are company record every member reads unless marked sensitive.
The owner's own decision covers a grant (send, spend, publish, sign, file), an invite, a share, outreach in approval mode, new access, widening permissions, a design change to a grant-holding agent and higher cadence or cost; per grant when critical.

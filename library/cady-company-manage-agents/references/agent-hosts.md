# Agent host tasks, library and silent hosts

**Point:** Keep each agent's host task, agent library and silent-host handling exact, so scheduled agents keep running.

- **Scheduling:** Wake for a useful action or signal, not to keep an agent busy. Every run is started by the computer's own CLI (`cady sync`): from the cadences registered there (cady script --every or --cron) and from Cady's signed requests, raised when an ask is answered or an approval is given (one run per agent per 15 minutes; a person may also run now). Cady keeps the work, checkpoints and results; only a reported result proves a run.
Every run of every agent follows the run sequence. Waiting work records its next action and due date and relies on the next run; there is no separate wake mechanism. Dated reminders (renewals, notice deadlines, filings) are due items in company work, read by the bound agent through work_read, never a separate reminder, calendar file or schedule.
Cadence: Reuse the authorized cadence and actual host or spend limits; otherwise fit cadence to evidence freshness and deadlines without inventing a time quota. Actionable work continues until done or an actual limit; waiting work checks near the expected reply or deadline and backs off empty checks; with no ready work, stop the run and keep the next useful trigger. Coalesce or skip missed runs; never replay a backlog of external effects. Distinguish a finite task from a continuing responsibility. Each run is short workhorse-tier triage. Dispatch ready tasks (filed, unblocked, with doneWhen and the needed authority) in priority order; while one remains and limits allow, take it in the same run rather than waiting for the next run. Start a new initiative or discretionary recurring work only when no ready task waits and usage has headroom (no host usage warning, rate limit or cost spike). With nothing ready, read what is due and exit. Learn of helper results from completion notices, not extra runs.
Since your last pass: read cady_read changes {since: the time saved on your work item, important: false}, paging with its cursor; after a complete pass save this pass's start time, overlapping the boundary and deduplicating change ids. A change pointer is a reason to re-check, never a completion verdict.
Runtime: Choose the lightest capable runtime: a script for deterministic work, a cadence registered with the computer's CLI for periodic work, an always-on external agent only when response time justifies its cost and security burden. Verify the actual host's persistence and tools before promising unattended work; a computer that is off cannot run the agent.
Runs: there is no host schedule to install or bind. Register the cadence with the computer's CLI (cady script --every or --cron); Cady's signed requests start the rest. The owner gives the go-ahead to live.
Models: The host owns model and effort selection. Preserve explicit user settings and use supported host controls; when selection is unavailable, use the configured executor.
- **Library:** Adopt the company's roster, not the whole library. An agent's skills are plain names, the skill folders the host holds; the library's cady-core-skill-index lists them, and Cady serves no skill index. The library's install.py copies the company system (the Executive and the orchestrator) and the core skills into the host's skills folder on the first run. Then `--add <agent>` copies each agent the Executive designed and the owner approved (its role card, its function's skills and the skills the card lists from others), `--stage <name>` copies a stage roster, and `--remove <agent>` retires one. The copies are the company's own: there is no lock, no sync and no update command. Preload each agent's role card in its agent file where the host supports it (Claude Code: the skills: list in .claude/agents/ preloads; it does not restrict the rest). Bind what you adopt and record the adoption and its reason in the work result. To take a library change, the Executive reads the library CHANGELOG.md since its last agent review (material changes only, each with an impact note), adopts what helps and edits the company's local skill, recording why. Contributing a change upstream is optional.
- **Silent hosts:** A silent host's agents. Look at your other hosts at most once a day (agents_read: each host's lastContactAt and, for a host silent 72 hours or more, each live agent's moveTo). A host in contact: skip its agents unless you detect and confirm a severe risk (for example an agent sending out poor content); then pause that agent first and tell the owner. A silent host's agent: if moveTo.here is true, move it here (agents_set host {action: move}, agentId, expectedRevision) and tell the owner in one line; if moveTo is another host, skip it; if moveTo is null, pause it (agents_set status paused with a note) and raise one ask to its owner to pause or retire it (moveWhy says why). The owner may also set one other computer as an agent's fallback: Cady's signed request goes there when the first stays silent. The server takes a move only from the host moveTo names; in the web app the owner moves an agent. Retire only an obsolete agent.

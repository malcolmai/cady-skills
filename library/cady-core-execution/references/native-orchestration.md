## Native orchestration

- **Continuation:** Persist material accepted decisions, exact source and artifact references, checks, unresolved work and uncertain effects with their existing owner at a handoff or checkpoint; keep routine progress in run logs. Refresh changed source, permission and work state before reusing conclusions. A helper reaching an actual host or provider limit returns partial work to the lead; the lead continues independent authorized work and checkpoints only the affected gap. Requesting cancellation is not acknowledgment: reconcile host worker status and any external effect before release or resumption. Cady task release does not cancel either. If every host is off, report work awaiting an execution resource rather than claiming a schedule or run.
- **Coordination:** Plan useful independent authorized work to advance concurrently when the benefit warrants total resource cost; priority alone does not create a dependency. Wait only for inputs, decisions or resources needed by the next action. Overlap agent preparation within actual host concurrency, memory, account/provider and authorized spend limits. Identify real human delivery and provider constraints without treating agent preparation as one person's sequential workload. Give each helper a disjoint write scope; claim shared heavy resources (test databases, browsers, provider sessions) through one owner and release them on exit; serialize what cannot be isolated. The lead reconciles returned work against current state and existing owner contracts. Parallel preparation does not authorize parallel account writes or external commitments.
- **Fan out:** Size fan-out to the company plan and actual host concurrency, usage and memory limits; split only substantial orthogonal work or independent framing. Pick by tier; read the model registry with get_execution_guide(topic="models"), never use a remembered model name: review is for key plans and independent reviews with fresh context; lead runs helpers and integrates; workhorse writes and retrieves; vision finds visual and journey issues; scripts take deterministic work. Use supported delegation depth and resource limits. Never put a lead- or review-tier writer under a lead. Keep concurrent helpers within max_parallel, keep RAM below about 80% and disk above 5 GB, and clean up finished resources before adding work. On a model rate limit, back off (about 1, 3, then 10 minutes) on the same model or move to another workhorse-tier model; never move bulk writing to lead or review by default.
- **Handoff:** Give each helper a bounded outcome, non-goals and acceptance criteria. Include the parent decision and relevant method, accepted and consequential rejected assumptions, exact source/artifact references with revisions and coverage, contradictory evidence, dependencies, disjoint write scope, effect authority, stop condition and actual resource limits. Return, in a file or owner record the requester reads rather than only a transient notice, the artifact or owner reference, checks actually run, changed assumptions, unresolved effects and next dependency. A clean child gets enough context to work independently without unrelated history or secrets; an inherited fork is not clean. For read-only rehearsal, return the exact artifact without pretending it was saved; durable continuation uses the existing task or owner.
- **Host boundary:** The host owns spawning, model/effort, permissions, concurrency, actual limits and cancellation; use current host settings. Delegate natively within user scope, host policy and resource limits; reuse applicable authority. Verify host capabilities; assume no universal default. Before proposing a Cady feature, check native coverage and state at most two material limits. If delegation is unavailable, continue directly and disclose material review limitations. Helpers gain no additional authority over company actions, external effects or schedules. A cross-host handoff transfers bounded task context and evidence only; live-host and managed-claim restrictions still govern, and helpers do not inherit persistent-agent status or effects authority.
- **Integration:** After the initial assessment, reconcile relevant context, the producer's rationale and counterevidence; revise findings when warranted. The lead verifies coverage and objective invariants with tools where possible, inspects ambiguities and consequential decisions, and samples routine work proportionately. Resolve disagreements against acceptance and evidence and verify the integrated result. A helper's report is evidence, not proof: inspect the actual diff or artifact and read consequential effects back before relying on them. Revisit prior failed or unrun checks and independent review findings; rerun affected checks when proof is missing, stale or inconsistent, or consequence warrants it; a check result names the revision and clean tree it ran on and is reused there, not repeated; otherwise it counts as not run. Feed changed customer-value or scope evidence to the Product decision owner; Execution revises dependencies and delivery against the accepted decision. Mandatory owner and release checks still apply. Preserve sound work. Reassess affected claims when source, artifact, scope or authority changes; previous review covers only the result it examined.
- **Review:** Use a separate reviewer when important uncertainty or consequence warrants fresh judgment, not for every edit. Where supported, start with fresh, minimal context: a neutral goal, criteria, constraints, actual artifacts and versions, and relevant evidence. Initially withhold the producer's verdict, preferred answer and evaluative labels; retain factual failures, accepted requirements and safety constraints. Use one reviewer in three stages, in order. Cold: only the artifact and a one-line statement of its reader; the reviewer answers the reader tests in the reader's words. Fit: add the owner's taste decisions and the agent's reader tests. Reconcile: add the producer's reasoning only after the reviewer's own verdict is recorded. A reread in the producer's own context is not a second reader. Inspect the actual proposal and dependent artifacts against their sources: do the decision, handoff, owner, permission, count and completion claims hold? Treat a proposed instruction as consequential even before a send or owner write; a role that can resolve a hold need not own procedure adoption. Review the combined change once, rank findings by consequence and rerun only the checks you doubt or the producer did not run, at the reviewed revision. Return concrete defects to the producer, then, in at most one further round, check changed passages and dependent artifacts before claiming completion. Ask for evidence-backed strengths, material issues and uncertainty; a positive or no-change assessment is valid. The reviewer states its basis, material prior exposure and coverage limits. Inherited history is not blinded review; disclose it rather than claiming independence from unseen context. A helper is not automatically an authorized QA reviewer, and agreement does not verify sources or eliminate shared blind spots.
- **Selection:** Start from the requested result, current responsibility, accepted company priorities and existing work. Choose the simplest capable route from verified host capabilities and current resources: one context for small coupled work; a continuing host session for recurring judgment when continuity is reliable; existing owner-backed finite work with replaceable workers when interruption or several hosts require handoff; an existing typed owner command for repeatable consequential effects. A task assignment or connected host is not execution or authority. Use the company agent-management method for host setup and scheduled_model_selection for recurrence; preserve explicit user model and effort settings. A routine failure or rate limit never automatically promotes work to a premium model. Native helpers suit independently useful results or review when their handoff and integration cost is justified. In GTM and Product, select the relevant role method (get_cady_context with a gtm/* or product/<id>/* area); Product owns value, outcome and scope, while Execution owns dependencies, allocation, integration and delivery. Inline role work stays in the host context. A separate conversation is for a revisitable workstream, not a helper or authority workaround. Verify clean-child support: forks inherit history, and an inherited reviewer must disclose prior exposure. Neither a child nor another conversation creates a Cady task or spend authority. At planning or agent design, identify currently knowable plan-critical input, access, provider account, tool, scheduler, credential-custody and grant gaps. Verify available reads first; prepare independent work, then consolidate unresolved asks with why, smallest scope, owner and next step. Never request secrets in chat or repeat unchanged owner-confirmed consent; ask later only for newly discovered or materially changed gaps. Future dependencies may still emerge.
- **Quality check:** Always check the actual result against the requested outcome and intended use before handoff or effect; tool success or file creation alone is not completion. Before a consequential multi-step effect, run one read-only pass that reports every failed precondition, not just the first, judging external systems against a real read refreshed on a schedule rather than an assumed shape. Fix what it finds as one batch, then rerun the audit and the effect once. For simple, high-confidence work, a deliberate second glance for material omissions is enough. Otherwise, before planning, set objectives and success criteria from the request, task acceptance, company goal, functions and key risks, independently of the drafted answer and your plan; for multi-step or consequential work, a fresh helper that has not seen the plan writes them where supported. Select checks suited to the work's purpose, domain and consequences. Compare material values and their field roles, not merely whether a token appears; checking one binding does not verify the others. Confirm source/scope, plausibility and effect authority, using a distinct calculation or evidence path when it covers a material failure. A passing mechanical check does not establish professional or recipient fit. Correct material defects and rerun affected checks. Preserve sound work. Then grade each criterion met, unmet or unchecked, citing receipts or readbacks and separating mechanical checks, judgment and observed outcomes; disclose an unresolved or unrun material check as an exception, never as checked. A self-grade is evidence, not independent review: use fresh independent review when important uncertainty or consequence warrants it. Stop when the finish line is met and acceptance passes; do not manufacture proof. When a fact, source or decision changes, chase its dependents and correct them before closing; a correction that leaves a dependent claim standing is not complete. An apparently stale item is not itself a cleanup mandate. If exact current owner state confirms supersession and no active work or uncertain effect depends on it, you may use an existing owner-provided reversible retirement with its required reason and current revision, then read back the receipt while preserving history. Age, silence, similar wording or agent inference alone do not establish supersession. Leave uncertain or owner-review items alone; never directly delete records, host tasks or source history.

## Delivery completion

- **Check:** Check the final result against the company's named critical paths, user journey and failure states; a poor flow fails acceptance. Distinguish known test-infrastructure failures from product failures with evidence. Use small deterministic checks for key edge cases; agent runs do not replace them. For a complex agent workflow, run one realistic, correctly scoped scenario covering several concerns; a fresh reviewer then checks its output and full transcript against each concern and the product's goal, and only then reads the agent's self-grade. A concern the run did not exercise stays unchecked. Per change, run the deterministic checks it touches; run the realistic end-to-end scenario once, on the final shape, and rerun a scenario only where a later change touches its concerns, and run independent scenarios in parallel within memory. Start confidence-threshold and broad edge-case campaigns only after the base case runs well; prefer reasoning and prior research to A/B tests. Label simulated, syntax-only, rendered, functional and independently reviewed evidence distinctly. Repair material defects and rerun affected checks after the last relevant change. Do not call a generated screenshot visually inspected or a syntax exit a functional test. A claimed helper or passing command is not proof of review or quality.
- **Handoff:** Read back the exact task and affected domain owner after checking the final artifact and before marking the selected task complete. For Product work, include the supported outcome, artifact and remaining evidence in the existing result. Do not imply a Product owner transition from a completed work item. Record the artifact/system reference, achieved outcome, limitations, review posture and unresolved work in the existing result; name checks actually run against the final artifact and state unrun or unobserved checks plainly. Carry forward the existing owner binding needed for continuation, including the operation's known subject and destination, rather than reconstructing it from names or narrative. Preserve the selected responsibility and task with their known revisions, applicable exact strategy/group revisions, owner result and material decision/artifact source references, logical-operation key and pending next action. Missing bindings remain unknown. An unrelated preferred role does not replace the selected assignment. Compare these material values and roles with owner/source readbacks; a strategy revision alone does not verify task or responsibility revisions. Typed delivery is host-reported. A go means ready to release; only the release owner records released with a receipt verifying the deployed artifact and target. Distinguish released from customer-validated. Reconcile uncertain effects before retrying and never widen external authority from task selection. For managed work, use existing claim and recovery fences, report_company_work for the result: a report means complete, and a wrong result is corrected later; a completed report is not business success. A cross-host handoff delivers the exact task and evidence, not permission to rebind a managed task or migrate an agent. If no allowed transition exists, retain an exact actionable handoff and continue safe work.
- **Scope:** Use the exact selected Projects task: its statement, acceptance, nextAction, evidence refs and, when present, goalId, agentId, dependsOn and productId. A goal is priority evidence, not task identity or effect authority; a direct one-off needs no invented goal or agent. Read immediate parent and dependencies when they change the next decision; use exact owner selectors and disclose missing, denied or stale coverage. This method applies to a broad deliverable in any business, not a first-product or software mandate. For an actual first company product and route to customers, also apply company review Setup (launch). Load only the relevant domain method. Reuse a complete selected skill body already served rather than refetching it; one or two preparation reads is a usability target, never a cap on needed investigation.
- **Work:** Continue useful authorized work through the company's chosen systems and host-native tools until acceptance or a justified dependency wait. Keep independent work moving when a dependency or actual limit affects only another action; a Cady task is continuity, not a host runner or extra authority.
- **Job:** Complete the authorized company outcome through a suitable executor with a verifiable result and recoverable continuation; understand the assignment’s parent purpose and relevant adjacent work when they change the next decision, make in-scope choices and continue safe work through minor uncertainty, and pause only your own affected behavior when continuing it would be clearly detrimental.

# Behaviour test

**Point:** Fix the metric, the lines and the decision each triggers before any work, so the result changes a decision.

Register it as a task (work_set {kind: task, headline: the assumption, brief}); put the full design in a File the task cites, and cite the question it tests when there is one. The task holds: the assumption; one behavioural metric, what people do (sign up, pay, return, reply), never what they say (interview enthusiasm, survey intent and likes are not demand); a pass line and a fail line; the decision taken on each outcome; the sample size and time box; stop conditions; and a sourced cost ceiling or an explicit unknown. Zero incremental external cost is the evaluation fallback without a selected budget; any paid effect requires checked current authority. Prepare everything yourself and come to the person only at a boundary (a call, filming, spend outside verified authority, a send, a signature, access) with a ready packet. When the user requested validation, leave a scoped next action on the resulting work; retire or replace a prior next action only after checking the exact current work and confirming the successor, with work_set {id, next}. A sound test changes a decision, tests the risky assumption, measures behaviour against lines set and held beforehand, has enough sample to tell, and stops on time.
